# Spec 04: AI Narrative Layer

## 1. Goal

Build the narrative service and visualization data service that convert diagnostic results into a client-ready slide deck. After this spec, calling `GET /diagnostic/{run_id}/slides` returns a complete slide deck JSON with 12 slides, each containing narrative text (Claude-generated), visualization data (deterministically computed), and layout metadata. The narrative is generated via 2 Claude API calls and validated for consistency with the metrics.

**Measurable outcome:** The slides endpoint returns well-formed JSON for all 12 slides. Narrative text references accurate dollar amounts. Visualization data matches the metrics engine output exactly.

## 2. Exemplar

**Narrative prompt engineering:** Reference Anthropic's structured output patterns. The prompts define exact JSON output schemas for both diagnostic and action plan narratives.

**Visualization data service:** Pure Python functions that transform metrics JSON into chart-ready data structures (arrays of objects matching Recharts' expected format). No exemplar needed — it's mechanical data reshaping.

## 3. Constraints

- **Two Claude API calls** for narrative generation:
  1. Diagnostic narrative (slides 2-7, 11-12): diagnosis + metrics + trends → per-slide text
  2. Action plan narrative (slides 8-10): action plan + diagnosis → per-slide text
- **Visualization data is NEVER generated by Claude.** The viz_data_service produces deterministic chart configs from metrics. This prevents hallucinated numbers in charts.
- **Narrative consistency validation (post-generation):**
  - Extract all dollar amounts from narrative text (regex: `\$[\d,]+`)
  - Cross-reference against metrics JSON — every dollar amount must trace to a known metric
  - Extract percentage claims and validate similarly
  - If any check fails, log warning but don't block (surface to frontend as a data quality indicator)
- **Fallback narratives:** If Claude fails, generate template-based narratives: "Property {code} {unit_type} has an occupancy of {occupancy}% with {vacant} vacant units." These are less insightful but factually correct.
- **Slide deck JSON schema:**
  ```json
  {
    "slides": [
      {
        "slide_number": "int",
        "slide_type": "str",
        "title": "str",
        "narrative": { "...per-slide narrative fields" },
        "viz_data": { "...chart data for this slide" },
        "layout": { "...rendering hints for frontend" }
      }
    ],
    "metadata": {
      "generated_at": "datetime",
      "property_ids": ["uuid"],
      "config_id": "uuid",
      "run_id": "uuid",
      "narrative_fallback": "bool"
    }
  }
  ```
- Each of the 14 visualization types must have a corresponding data generator function in viz_data_service.
- Max 25 words per executive summary bullet. Max 4 sentences per slide narrative block.
- Narrative text must address client directly ("Your B1 units...").
- No markdown formatting in narrative text (no `**bold**`, no `# headers`). Frontend handles all styling.

### Slideshow Structure (12 Slides)

1. **Title** — static template (property name, date, "Pricing Health Diagnostic & 30-Day Action Plan")
2. **Executive Summary** — SCORE_GAUGE + KPI_CARDS (4 cards) + Claude headline + 3 key findings
3. **Portfolio Snapshot** — DATA_TABLE with full export data, conditional cell coloring
4. **Property A Deep Dive** — DUAL_SCORE_CARD + RENT_WATERFALL charts + Claude narrative
5. **Property B Deep Dive** — same format, B1 crisis emphasis
6. **Trend Analysis** — LINE_CHARTS 2×2 grid (occupancy + asking + comps per unit type, 4 months)
7. **Revenue at Risk** — STACKED_BAR vacancy cost + DAILY_BURN_COUNTER ($911/day)
8. **Action Plan Overview** — TIMELINE (4-phase) + action/experiment counts
9. **Phase 1 Detail** — ACTION_CARDS (2×2 grid) + EXPERIMENT_DIAGRAM (arm splits)
10. **Day 15 Decision Tree** — DECISION_FLOWCHART (branching paths per unit type)
11. **Further Investigation** — INVESTIGATION_TABLE (area, questions, data needed, deadline)
12. **Summary & Next Steps** — BEFORE_AFTER comparison + top 3 priorities

### 14 Visualization Types and Data Formats

```
SCORE_GAUGE:
  { score: int, max: 100, zones: [{min, max, color, label}] }

KPI_CARDS:
  [{ label: str, value: str, format: str, color: str, trend: str }]  # 4 cards

DATA_TABLE:
  { columns: [{key, label, format}], rows: [{...cell values}], highlights: [{row, col, color}] }

RENT_WATERFALL:
  [{ label: str, value: float, type: "base|addition|subtotal|comparison", color: str }]

DUAL_SCORE_CARD:
  [{ unit_type: str, score: int, grade: str, color: str, key_metric: str }]

LINE_CHARTS:
  [{ unit_type: str, series: [{ month: str, occupancy: float, asking: float, comps: float }] }]

STACKED_BAR:
  [{ unit_type: str, vacancy_cost: float, color: str }]

DAILY_BURN_COUNTER:
  { daily_amount: float, monthly_amount: float, annual_amount: float }

TIMELINE:
  [{ phase: int, title: str, days: str, actions_count: int, experiments_count: int, color: str }]

ACTION_CARDS:
  [{ title: str, unit_type: str, action_type: str, target: str, urgency: str, border_color: str }]

EXPERIMENT_DIAGRAM:
  { unit_type: str, arms: [{ label: str, price: float, units: int, color: str }], window_days: int }

DECISION_FLOWCHART:
  [{ unit_type: str, condition: str, outcomes: [{ label: str, action: str, color: str }] }]

INVESTIGATION_TABLE:
  [{ area: str, questions: [str], data_needed: str, deadline: str }]

BEFORE_AFTER:
  [{ metric: str, current: str, projected: str, improvement: str, color: str }]
```

### Claude API Call Structure (3 total in pipeline)

1. **Diagnosis call** (from Spec 03): produces diagnosis_json
2. **Action plan call** (from Spec 03): produces action_plan_json
3. **Narrative call** (this spec): 2 sub-calls producing per-slide narrative text:
   - Sub-call A (diagnostic narrative): slides 2-7, 11-12
   - Sub-call B (action plan narrative): slides 8-10

### Narrative Tone & Style

- "Senior revenue manager presenting to a client VP of Operations"
- Confident, specific, data-driven
- Not salesy, not hedging
- Address client directly: "Your B1 units..." not "The B1 units..."
- Plain text only — no markdown formatting
- Every dollar amount must trace to a known metric value

## 4. Anti-Patterns

- **Do NOT** let Claude generate chart data, numbers for KPI cards, or any numerical visualization content. Claude generates TEXT only.
- **Do NOT** pass the full rent roll to Claude. Pass only the aggregated metrics JSON — Claude doesn't need unit-level data for narrative generation.
- **Do NOT** generate all 12 slides' narrative in a single Claude call. Use 2 calls as designed (diagnostic + action plan) for reliability and parallel potential.
- **Do NOT** skip the consistency check. Even if it seems redundant, dollar amounts in narrative text MUST be validated against source data.
- **Do NOT** return partial slide deck JSON if some slides failed. Return all 12 slides — use fallback narrative for failed slides, but always include viz_data.
- **Do NOT** include markdown formatting in narrative text (no `**bold**`, no `## headers`). The frontend handles all styling.

## 5. Scenarios

1. **Complete slide deck for Property B:**
   - Slide 2 (Executive Summary): headline mentions B1 crisis, KPI cards show correct vacancy cost ($17,549/mo for B), portfolio score rendered.
   - Slide 5 (Property B Deep Dive): B1 narrative uses urgent language, references "$91 above comps", "$254/day vacancy burn". B2 narrative flags the "priced right but not leasing" puzzle.
   - Slide 7 (Revenue at Risk): STACKED_BAR shows B2 as tallest bar ($9,924). DAILY_BURN_COUNTER shows $911/day total.
   - Slide 9 (Phase 1): ACTION_CARDS show B1 price cut with target $1,475. EXPERIMENT_DIAGRAM shows B2 three-arm split.
   - Slide 10 (Decision Tree): Three branching paths for B1, A2, and B2.

2. **Narrative consistency check:**
   - If narrative says "$1,525" for B1 asking rent, this must match metrics.pricing_spreads.asking_rent for B1.
   - If narrative says "25% exposure", this must match metrics.exposure_metrics.total_exposure_pct for B1.
   - Test with an intentionally wrong narrative (mock Claude returning wrong number) — consistency check should flag it.

3. **Fallback scenario:**
   - Mock Claude returning invalid JSON on first call, timeout on retry.
   - Slide deck still returns with all 12 slides.
   - Narrative fields contain template-based text.
   - Viz data is unaffected.
   - Metadata indicates "fallback_narrative: true".

4. **Viz data accuracy:**
   - RENT_WATERFALL for B1: bars at Base=$1,405, +Amenity=$125, =Predicted=$1,530, Asking=$1,525, Comps=$1,434. The bracket between Asking and Comps shows +$91 (+6.3%).
   - LINE_CHARTS for B1: Dec occupancy=0.88, Jan=0.83, Feb=0.79, Mar=0.79. Asking: $1,600→$1,575→$1,540→$1,525. Comps: $1,475→$1,460→$1,445→$1,434.
